# IoT System v1.0.0

`v1.0.0` is the first stable portfolio release of the IoT System repository.

## Release Summary

The release demonstrates an end-to-end embedded telemetry path from STM32 sensor acquisition to a React dashboard, with explicit durability boundaries between radio transport, gateway storage, MQTT delivery, backend ingestion, and time-series storage.

## Included Components

| Component | Role |
|---|---|
| Node 01 | STM32F103 internal-ADC temperature sensing node |
| Node 02 | STM32F103 internal-ADC temperature sensing node |
| Node 03 | STM32F103 + MCP3208 temperature sensing node |
| ESP32 Gateway | LoRa polling, LittleFS durability, MQTT QoS 1 forwarding |
| Mosquitto | Authenticated MQTT broker with persistence |
| Backend | Durable ingestion, InfluxDB writer, REST API |
| Frontend | React dashboard for live and historical telemetry |

## Reliability Highlights

- LoRa DATA/ACK exchange with sequence numbers, retry, and duplicate detection.
- Gateway persistence to LittleFS before acknowledging a sensor node.
- MQTT QoS 1 delivery with queued records retained until PUBACK.
- Broker persistence for restart recovery.
- Backend filesystem spool before committing data to InfluxDB.
- Replay-safe handling for temporary database outages.

## Verification

GitHub Actions verifies these repository gates:

1. Repository Hygiene
2. Backend
3. Frontend
4. Gateway

The ESP32 Gateway is built with the pinned Pioarduino ESP32 platform so the Arduino-ESP32/ESP-IDF toolchain is reproducible in CI.

STM32 node firmware is maintained as Keil MDK projects and is verified separately from GitHub Actions.

## Release Assets

The GitHub release should contain:

- `iot-system-v1.0.0-source.tar.gz`
- `SHA256SUMS`

GitHub also provides automatically generated source archives for the tag.

Gateway or STM32 firmware binaries should only be attached when they were built from the release tag with the intended deployment configuration. Secrets and local credentials must never be packaged.

## Known Limitations

- STM32 CI is not automated because the current firmware projects target Keil MDK.
- OTA firmware update support is not included.
- Production-grade end-user authentication is outside the current scope.
